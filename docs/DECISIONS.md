# Decisions

Where the build departs from [PRD-001](prd/PRD-001-ephemeral-runners.md) or fills a gap, and why. Newest last.

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-11-14 | **Terraform deployed by azd, one root** (`infra/`) built from shared modules (state backend created by a preprovision step, Log Analytics, registry, Key Vault, Container Apps environment), instead of `infra/bootstrap` + `modules/` + `envs/dev`. The runner job is the project's own file and module. | Same Entra-authenticated state, preview before apply and a clean teardown, with less code to maintain; tags a tenant requires come from the azd environment (`RESOURCE_TAGS`), never from files. |
| D2 | 2026-11-14 | The JWT's issuer is the Registrar App's **client ID** (`GH_REGISTRAR_CLIENT_ID`). | GitHub's documentation recommends the client ID over the app ID. |
| D3 | 2026-11-14 | GitHub REST calls send `X-GitHub-Api-Version: 2026-03-10`. | The latest supported version (`GET /versions`); the JIT endpoint and its body are unchanged in it. |
| D4 | 2026-11-14 | The image adds only the Azure CLI, the GitHub CLI, Node LTS and `libatomic1` (Node needs it). Node comes as `.tar.gz`. | `curl`, `jq`, `openssl`, `git` and Python 3 are already in the official image; it has no `xz`. |
| D5 | 2026-11-14 | Retries use curl's own (`--retry 2`: 3 attempts on 408, 429 and 5xx, with backoff and `Retry-After`). | The brief's behaviour without a retry loop of our own. |
| D6 | 2026-11-14 | Secrets stay in shell variables; the private key reaches `openssl` through a file descriptor, headers through stdin. | Nothing on disk and nothing on a command line, except the JIT configuration that `run.sh --jitconfig` requires (see [SECURITY](SECURITY.md)). |
| D7 | 2026-11-14 | The repository is public; its own CI and image builds run on GitHub-hosted runners. | Public repositories don't use the minutes these runners are meant to save. |
| D8 | 2026-11-14 | The workflows that run **on** these runners (`smoke-test.yml`, later `print-oidc-claims.yml`) live in `examples/target-repository/`, to copy into the private repository they serve. | Self-hosted runners must never take jobs of a public repository, whose pull requests come from anyone. |
| D9 | 2026-11-14 | Workflows request `runs-on: aca-agent` alone, not `[self-hosted, aca-agent]`. | A runner registered with `generate-jitconfig` reported only the labels it was given (`aca-agent`), none of the default `self-hosted`, `Linux`, `X64`: a job asking for `self-hosted` would never match it. The scaler counts `aca-agent` with `noDefaultLabels`, so all three agree. |
| D10 | 2026-11-14 | Terraform creates the two key secrets with a **write-only placeholder** (`value_wo`); the real keys are uploaded by hand as new versions. | A role assignment needs its scope to exist: this keeps the runtime identity's Key Vault Secrets User role on the two secrets only, not on the vault, while no key, and not even the placeholder, reaches the Terraform state (`value_wo` is stored as null). Needs Terraform 1.11 or later. |
| D11 | 2026-11-14 | The optional `infra` identity (a workflow running this Terraform) comes with that workflow in Phase 6, not in Phase 2. | Nothing uses it before then. |
| D12 | 2026-11-14 | Memory is derived from the vCPUs (twice), not a separate setting. | On the Consumption profile those are the only valid combinations. |
| D13 | 2026-11-14 | Jobs needing Docker or Podman (e.g. a dev-container build) stay on GitHub-hosted runners. | In the job, Podman found no `/dev/fuse`, no user namespaces and cgroups v1 (experiment 03). |
| D14 | 2026-11-14 | The image includes uv (0.13.8); the system Python is 3.12. | The target repository's jobs need uv with Python 3.12. |
| D15 | 2026-11-14 | The scale rule uses `enableEtags=false`, and the entrypoint removes a runner that gets no job within `RUNNER_IDLE_TIMEOUT` (300 s). | With ETags the scaler counted one queued job twice and kept counting a completed run, so idle executions restarted every six minutes (experiment 04). Without them, a few hundred more API calls an hour, far below the App's limit. The watchdog covers cancelled runs and any double count left (KEDA counts runs from two requests without removing duplicates). |
| D16 | 2026-11-15 | The federated credential's subject is a setting (`RUNNER_DEPLOYER_OIDC_SUBJECT`), read from a real token's claims. | The target repository's tokens carry `repo:<owner>@<owner id>/<repo>@<repo id>:environment:<environment>`, not the classic `repo:<owner>/<repo>:…` the default assumes (experiment 05). |
| D17 | 2026-11-15 | The GitHub environment `azure-dev` accepts the `main` branch only. | Any branch's workflow could otherwise sign in as the deployer identity. |
| D18 | 2026-11-15 | The Copilot cloud agent stays on GitHub-hosted runners for now. | On self-hosted runners its integrated firewall must be turned off, and these runners have open outbound access until private networking (Phase 6) brings egress control. |
| D19 | 2026-11-15 | A monthly budget on the resource group, alerting the resource group's Owners (`contact_roles`), its amount a setting (`BUDGET_AMOUNT`, 0 for none). | Alerts reach the owner without an e-mail address in any file or setting; a budget alerts and stops nothing. |
| D20 | 2026-11-15 | Egress control is an allowlist proxy (Squid in an internal Container Apps environment) plus a network security group that denies the runners' subnet the internet, behind `EGRESS_PROXY`. The subnet still allows the platform's service tags, Key Vault in the region and GitHub's API addresses. | Azure Firewall Basic costs about 259 € a month (0.3546 € an hour, retail price, francecentral) before traffic; the proxy is one small replica. The scale rule's scaler and the job's Key Vault reference work from the runners' subnet without the proxy, so they need those rules (experiment 06). The proxy sees host names, never content (no TLS interception). |
| D21 | 2026-11-15 | Private networking (`PRIVATE_NETWORKING`): a private endpoint for Key Vault, off by default; the vault stays public with Entra authentication. The registry gets no private endpoint. | Turning off the vault's public access needs every client inside the network, the deployer's machine included. A registry private endpoint needs the Premium SKU; pulls already use Entra authentication. |
| D22 | 2026-11-16 | The public CI checks the Terraform offline only (format, validation, tflint, Trivy, `terraform test` with mock providers); plans and applies run from the maintainer's machine. | A plan in a public repository's logs would show the subscription, resource IDs and settings. |

## Open

- **Passwordless sudo:** the official image gives the `runner` user passwordless `sudo`, so job steps can become root in the container. Many actions rely on it (package installs). Even as root, a step found no identity header and got 403 from the endpoint (experiment 03); kept.
- **Image size:** 2.5 GB (775 MB compressed): pulled in 15 s, 36 s from an execution's start to its job (experiment 03). Not worth slimming for now.
- **Copilot cloud agent:** GitHub recommends ephemeral, single-use runners for it, which these are, and requires its integrated firewall off on self-hosted runners. With the egress proxy (D20), it can now be tried (D18).
- **Self-hosted runner billing:** self-hosted minutes don't use the included minutes; a per-minute platform charge announced for private repositories was postponed (to recheck on GitHub's billing page before relying on it).
